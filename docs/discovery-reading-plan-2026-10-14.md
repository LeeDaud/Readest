# 发现书籍、已读清单与阅读时长改版规划

日期：2026-10-14
维护基线：`codex/zlibrary-integration` / Readest 0.12.16
状态：规划完成，尚未实施；本次仅新增规划文档

## 目标与范围

以 Android 手机 App 为首要验收平台，在现有 Readest Fork 中完成五项改造。沿用 Readest 名称、图标、主题与交互规范，保留 Z-Library 应用内搜索、用户选择版本、下载后自动导入的链路。推荐、已读清单、阅读统计各自承担独立职责。

UI 以 `apps/readest-app/DESIGN.md` 为准：内容优先、主题中性色、统一标题与返回、克制的强调色、原有列表和按钮原语；不在这次改造中继续扩大微信读书主题的改动。遵循安全区域、RTL、可访问性和电子墨水模式规范。

## 现状核查

| 现状 | 对本次规划的影响 |
| --- | --- |
| 推荐来自 `services/discovery/catalog.ts` 的 30 本内置书；Open Library 只补充封面与评分 | 需要实现在线候选获取，不能只调整内置数组或删除数量文案 |
| `discover/page.tsx` 同时包含推荐、手动记录表单和历史列表 | 拆成独立页面，推荐页保留单卡片与简单操作 |
| 在线资料需要点“获取封面与评分”；匹配要求书名、作者严格命中；未匹配结果缓存 7 天 | 自动补充资料、优先使用作品标识、区分暂时失败和确实缺失；是否为手机故障根因仍需实测 |
| Covers URL 未带 `default=false`，缺失封面可能是成功响应的空白图 | 显式检测缺失，失败时收起封面区域 |
| 首页右上角和导入菜单都有发现入口 | 去除右上角发现入口，只保留导入菜单入口 |
| 上游已有 `ReadingStatsTracker`、`TrackerCore` 和 `StatisticsDb` | 复用自动计时及数据库，补充统计查询和页面；不另起计时系统 |
| 默认单页闲置阈值 120 秒、最小事件 3 秒；可见性处理包含暂停，恢复阅读路径需核查 | 对用户说明统计为自动估算；重点验证后台恢复与静止阅读，避免漏记或后台累加 |

## 页面与入口

| 位置 | 行为 |
| --- | --- |
| 首页原“导入书籍”入口 | 保留原导入方式，菜单中保留“发现书籍” |
| 首页新增“已读清单”入口 | 与导入按钮使用相同按钮样式、尺寸和点击反馈，独立可见；点击直接进入清单页 |
| 首页右上角原发现位置 | 替换为时钟类图标“阅读时长”，点击进入统计页，补充可访问名称 |
| `/discover` | 一次一本的推荐页，移除历史列表和添加记录表单 |
| `/read-history`（拟定） | 独立已读清单，可添加、编辑、删除和搜索记录 |
| `/reading-stats`（拟定） | 总阅读时长与分书籍时长；自动统计，无打卡或手动补时功能 |

首页空书架、有书架、分组视图和手机横屏都要能找到已读清单。新入口的位置跟随现有导入按钮，窄屏采用纵向排列，避免挤压书籍内容。Android 返回键、页面返回按钮及路由返回均返回合理位置，保留书架状态。

推荐主流程：书架 → 导入 → 发现书籍 → 左滑/换一本 → 感兴趣 → Z-Library 搜索 → 用户选版本并下载 → 自动导入书架 → 阅读。

## 发现页 UI

1. 顶部采用 Readest 子页面标题、简短说明和返回按钮；分类筛选保持轻量，不展示“剩余 N 本”或总推荐额度。
2. 主体仅一张卡片，信息顺序为书名、作者、简介。长书名允许换行；简介先展示适量正文，支持展开和正常纵向滚动。
3. 封面和评分为可选信息。评分显示来源、五分制和评分人数；缺失字段直接收起。两项均不可用时，仅展示书名、作者、简介，不留假封面、空星级或长期加载区域。
4. 自动加载在线资料，移除“获取封面与评分”操作；资料补充不阻塞卡片和换书，加载后保持稳定布局。
5. 核心操作为“去 Z-Library 找这本书”，次级操作为“换一本”和“已经读过”。左滑代表“不感兴趣”，保留可点击的替代方式与短暂撤销，避免误滑永久排除。
6. 区分纵向阅读简介与横向左滑。请求进行中防止重复提交；旧卡片的响应不能覆盖新卡片。电子墨水/减少动态效果模式不使用持续拖拽动画。
7. 原站书评作为弱化的辅助操作，保留现有应用内打开方式；卡片不声称已取得豆瓣评分或完整书评 API。
8. 首次加载、补充候选、离线、请求失败、没有符合条件的书均有明确状态与重试动作。当前卡片已可用时，下一批请求失败不清空当前内容。

## 持续推荐逻辑

“无限推荐”定义为：应用不设固定书单上限、每日额度或换书次数上限；用户可以持续换书，系统按需获取更多候选。外部数据库和当前筛选结果是有限的，网络及服务限流也需要正常处理，不能承诺数学上的无限且永不重复。

- 使用 Open Library Search API 获取候选，按现有分类映射主题查询。默认优先适合中文用户的可用版本；保留原书名和作者，不伪造中文译名。中文结果不足时可换主题，并明确提供扩大语言范围的选择。
- 采用小批量获取和小队列预取，初始建议每批 20 本，剩余约 3 本时预取。这个数量是每次网络请求的批量大小，不是推荐总量限制。
- 每个查询记录已访问的范围；同一轮使用稳定分页顺序并在本地打乱，避免不断重排导致漏项。新的查询轮可使用 API 随机排序和本地去重，但不把随机分页当作无重复保证。
- 使用 Open Library Work ID 作为在线作品身份；同一作品不同版本优先合并。旧记录或手动记录没有 ID 时，使用 ISBN、书名与作者及已知别名辅助匹配；不能靠低阈值模糊匹配将不同书合并。
- 持续排除已读、不感兴趣以及书架中已有的书，维护已展示记录。打开 Z-Library 搜索只记录选择行为，不代表已经下载或读完；已有书架导入事件用于确认入库。
- “换一本”记录已展示，左滑记录不感兴趣，“已经读过”写入已读清单。撤销只回滚此次不感兴趣操作；编辑/删除已读记录后及时重新计算排除条件。
- 筛选导致整批为空时继续读取后续范围或主题；以单次任务的时间预算中止等待，返回可重试状态，避免死循环。恢复后继续获取，不能退回固定 30 本并宣称已经扩展书单。
- 网络断开时使用已缓存且符合条件的候选；内置 30 本仅作离线启动备用，耗尽后明确提示联网，不循环推荐已读或不感兴趣的书。
- 共用请求调度器、缓存和请求合并，默认不超过 1 请求/秒；429/5xx 退避，遵循 Retry-After。退出页面取消不必要的请求，不批量抓取整站。

## 封面、评分与简介修复

按下列顺序实施并在 Android 上验证：

1. 观察真实请求：区分 HTTP 插件调用、网络可达性、接口返回、解析/作品匹配、图片加载与缓存命中；不只依赖 Web 模拟接口。
2. 在线候选直接沿用 Search 响应中的 Work ID、封面 ID 和评分字段，避免再次按翻译后的书名搜一遍。已有精选书单按作品 ID 或可靠标识补充资料；不因放宽字符串条件展示其他书的资料。
3. 封面优先使用 Cover ID/Edition OLID；必要时尝试已确认版本的 ISBN。URL 加 `?default=false`，处理 404、超时、格式异常、空白图；失败收起区域。
4. 校验评分数值、人数与来源；没有投票或字段缺失则隐藏评分，不使用 0 分代替。候选不因缺少评分或封面被排除。
5. 简介按需从作品详情获取，必要时使用匹配版本的 description，兼容字符串与 `{value}` 格式；处理空内容和过长文字，不展示内部对象或 HTML。
6. 简介不可用时，已知内置书可以使用其现有简介；在线书不能拼凑或虚构简介。优先补充可获取简介的候选，仍缺失时简短注明“暂无简介”，保持换书可用。
7. 区分成功资料缓存、确认缺失缓存与瞬时网络故障；故障不缓存成 7 天无资料，已有 null 缓存版本更新后允许重新获取。
8. 若实测封面/评分长期不可靠，采用上述文字卡片作为正式降级方案；保留来源标识供排查，不增加用户必须配置的 API 密钥或代理步骤。

## 已读清单与存储迁移

- 已读清单仅展示已读，推荐的已展示、不感兴趣、已选择记录单独用于推荐过滤，不混入“读完的书”。
- 必填书名，作者可选；可从本地书架选择已读书，也可手动添加未导入的书。支持编辑书名、作者和可选读完日期，日期不要求用户补齐。
- 添加或编辑使用现有 Readest 表单/弹层规范；保存后立即更新列表和推荐排除。删除提供确认或撤销，不影响书架文件或阅读时长。
- 独立数据层由推荐页和已读页共同调用，避免两套名单。保留稳定记录 ID、作品标识、来源和必要别名，使编辑展示信息时身份不丢失。
- 旧 `settings.bookDiscovery` 的 `read` 记录迁入清单；`dismissed/selected/seen` 保留各自语义。迁移可重复执行且不重复新增，只在持久化确认后标记完成，不删除原始数据作迁移前提。
- 不设置历史条目数量上限。随着在线候选增加，去重和历史数据使用现有本地数据库服务的独立表/数据库，分页读取和索引查询；不把不断增长的历史与资料缓存反复写进整份设置文件。
- 第一版以本机持久化为验收要求，退出和升级后保留；不声称新增清单已具备跨设备同步。未登录也可以使用。

## 阅读时长

- 复用 `ReadingStatsTracker` 和 `StatisticsDb`；基于现有事件聚合总时长和每本书时长，不启动第二个独立定时器重复计费。
- 页面顶部显示总阅读时长，下面是书名、作者、累计时长组成的 Readest 列表；按累计时长排序，长书名正常换行。零记录时引导打开书架阅读。
- 普通阅读在实际阅读页可见时自动计时；切后台、锁屏、离开阅读器停止，返回可见阅读页恢复。需实测 Android Activity 生命周期与 WebView visibility，必要时利用现有生命周期事件补齐。
- 单页长时间不操作沿用并验证上游 120 秒闲置策略；页面说明时长为自动估算，不能把静置亮屏无限计为阅读。检查触摸/滚动能否恢复或延续有效计时，避免只有翻页才恢复。
- 沿用上游朗读统计行为，同一书的朗读与页面阅读不能重复累计；不额外增加听书图表。多窗口/分屏核查活跃阅读实例，不能将同一段普通阅读时间重复计入两本书。
- 统计以书籍 hash 为身份，与已读清单的作品身份分开。重复导入同一文件不拆分；不同文件版本默认遵循 Readest 原有书籍身份，不在本轮做跨版本时长合并。
- 阅读时长与“已经读完”独立：计时不会自动标记读完，手动添加已读也不生成阅读分钟。删除已读记录不删除统计，删除书架文件保留已有统计和书籍标题。
- 已有可用事件进入统计；旧版本未采集的时间不追溯补造。本机持久化、数据库加载、升级后的延续均需验收。
- 不添加打卡、目标、连续天数、日历热力图、排行榜或手动补时入口。

## 实施顺序与涉及代码

| 阶段 | 工作与主要路径 | 交付条件 |
| --- | --- | --- |
| 1：基础与入口 | 拆出共享记录服务和迁移；新增 `app/read-history`；修改 `LibraryHeader`、`Bookshelf`、导入入口组件 | 已读清单独立可编辑，老数据完整；发现只有导入入口；统计位置确定 |
| 2：在线推荐与资料 | 扩展 `services/discovery` 候选获取、身份、详情、缓存和排除；改造 `app/discover` | 连续换书突破 30 本，资料自动获取或可靠降级，不重复推荐已读 |
| 3：UI 整体调整 | 单卡片、页头、操作区、缺失字段、手势和错误状态，复用 Readest 原语 | 手机窄屏、深色、电子墨水、大字体下可用，视觉与 Readest 一致 |
| 4：时长统计 | 新增 `app/reading-stats`；扩展 `StatisticsDb` 查询，验证并补齐计时生命周期 | 总时长等于分书累计口径，后台不误记，回到阅读能恢复 |
| 5：Android 回归与打包 | 更新相关单元/原生测试、构建验证；生成沿用签名的 ARM64 包 | 功能、迁移、阅读、Z-Library 搜索下载入库的完整链路通过 |

以上为分阶段开发，最终按五项需求一起验收。引擎、子模块和无关阅读器 UI 不改；尽量把新增逻辑留在独立页面与服务中，减少未来上游合并冲突。

## 验收清单

1. 首页发现图标消失，原位置进入时长统计；导入菜单仍可进入发现。已读清单有独立、与导入同样式的入口，空/非空书架均可用。
2. 一次仅展示一本。连续换书至少 100 次，候选明显超过原 30 本；测试跨批次、跨主题、重启恢复和全部被过滤的情况，不依赖清空已读/不感兴趣记录。
3. 单元测试覆盖在线响应、Work ID 去重、别名匹配、429/超时、队列耗尽和迁移幂等；无法通过 100 次真实连通性测试时，不以模拟响应宣称在线无限推荐验收完成。
4. 用有封面评分、缺评分、缺封面、缺简介、同名不同作者及网络不可达样本验证，确保不串书、不显示空白图或伪评分；两项缺失时卡片仅保留文本核心内容。
5. 左滑换书、纵向简介滚动、换书中旧请求到达、撤销、已经读过与 Z-Library 跳转在 Android 原生 WebView 中验证。
6. 已读清单添加/编辑/删除生效，老记录迁移、重启和覆盖安装后保留；操作不删除书架文件和统计。手动添加的书不再推荐。
7. 至少两本书分别阅读固定时间，检查总时长与分书聚合；后台/锁屏停计、恢复阅读、静置超过闲置阈值、朗读与分屏均检查；允许现有最小事件过滤带来的秒级差异。
8. 验证 EPUB 和 PDF 等实际支持格式的统计，不假设所有渲染路径都发同样的页事件。重新验证导入 → 阅读 → 返回书架流程。
9. 类型、相关 Lint、单元测试、静态前端构建、Android 原生测试通过后打包。Web 检查只作辅助，实体 Android 手机的真实站点下载入库另作必需验收。

## 外部接口依据

- [Open Library Search API](https://openlibrary.org/dev/docs/api/search)：支持分页、随机排序和作品/版本字段；语言偏好与语言过滤不同。
- [Open Library API 使用规范](https://openlibrary.org/developers/api)：默认 1 请求/秒，优先批量搜索，避免大量单书请求和批量采集。
- [Open Library Covers API](https://openlibrary.org/dev/docs/api/covers)：可按封面 ID、OLID、ISBN 获取；`default=false` 让无封面返回 404；部分标识类型有限流。

## 设计检查结论

本规划已明确入口分工、单卡片信息层级、主题继承、资料降级、加载/错误/空状态、手势替代、安全区域、长文本和旧数据保留。实际像素效果与 API 可达性待实施后验证，当前没有 UI 成品、Android 新安装包或新一轮通过测试的结论。

主要风险是中文书目与简介覆盖、真实网络可达性、作品身份匹配，以及 Android 后台/恢复计时。第一版先解决这些可验证的行为；不以增加装饰、扩大内置书单或重置记录替代核心修复。
